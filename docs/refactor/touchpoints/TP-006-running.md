# TP-006 — 운행 로그에서 날짜·노선별 운행 이력 테이블을 확인한다

> 전사 출처: F05 §4.2 + P4/W8 상세. 새 UX 발명 없음.

## 1. 맥락

- **누가 (actor):** 일반 사용자 또는 관리자
- **언제·왜:** 특정 날짜·노선의 실제 운행 이력(정류장별 통과 시각)을 확인하려 할 때.
- **위치 (surface/location):** `GET /running?route_id=195000178&date=20260601`
- **사전 상태 (precondition):** 로그인 불필요. `bus_timelog` DB에 해당 날짜 로그가 존재하면 그리드 표시.

## 2. 인터랙션 흐름 (Happy Path)

| # | 사람의 행동 | 시스템의 정확한 반응 | 화면/상태 변화 |
|---|---|---|---|
| 1 | `/running`으로 진입 | 200 + 기본값(첫 노선, 어제 날짜) 렌더링. 안내 배너 + 폼 + 운행 테이블 또는 빈 상태 | 운행 이력 화면 |
| 2 | 날짜·노선 선택 후 조회 버튼 | `GET /running?route_id=...&date=...` → DB 조회 → 정류장×운행 그리드 렌더링 | 운행 그리드 표시 |

## 3. 화면/상태 목업 (ASCII)

```text
┌──────────────────────────────────────────────────────┐

│   진목회관(시내)  │ 08:32  │ 10:17  │ ...              │
│  ...             │ ...    │ ...    │ ...              │
└──────────────────────────────────────────────────────┘
```

## 4. 입력 사양

| 입력 | 형식/제약 | 필수 | 기본값 | 검증 시점 |
|---|---|---|---|---|
| route_id | ROUTEID 키 문자열 | N | 첫 번째 route_id | server |
| date | YYYYMMDD 형식 | N | 어제 KST 날짜 | server (실패 → 경고+기본값) |

## 5. 피드백 규약

- **로딩:** GET 폼 제출. 서버 렌더링.
- **성공:** 정류장(행) × 운행 회차(열) 그리드 표시.
- **에러:** DB 연결 실패 → 사용자 친화 메시지 (`db_error`), 500 금지.
- **빈 상태:** 로그 없음 → "검색된 버스가 없습니다."
- **잘못된 날짜:** 경고 + 어제 날짜로 폴백.

## 6. 분기 (성공/실패/엣지)

| 조건 | 시스템 반응 | 사용자에게 보이는 것 |
|---|---|---|
| 정상 (로그 있음) | 200 + running-table | 정류장×통과시각 그리드 |
| 로그 없음 | 200 + empty-state | "검색된 버스가 없습니다" |
| DB 연결 실패 | 200 + db_error 배너 | 친화적 에러 메시지 |
| 잘못된 date 형식 | 200 + warning + 기본값 폴백 | 경고 + 어제 날짜 조회 |
| 미등록 route_id | 200 + warning + 기본 노선 | 경고 + 기본 노선 결과 |
